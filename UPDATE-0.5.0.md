# Silk Engine 0.5.0

## Install the source update

Quit Silk Engine from its tray menu. Extract the project and replace your previous project source (keep your media files). In the project folder:

```sh
npm install
npm test
npm run dev
```

For a new Windows installer, run `npm run build`. This ZIP contains source, not a compiled Windows installer. The application ID and configuration location are unchanged.

## Layout and interaction

The main card and right column share top and bottom edges on desktop. The right column contains a left-aligned display preview and a compact two-column control panel. At narrower widths the composition rearranges. The decorative background is quieter and long wallpaper titles wrap within the card.

Click the main wallpaper card to toggle its saved eagle setting. The card includes a keyboard-focusable toggle (Space/Enter); Customise and Pause remain separate buttons. The visible Eagle on/off button is removed. Text/panel drag-selection remains disabled, while editable fields and incoming file drops work normally.

## Simulation previews

Cards, the display map, the hero and the settings sheet receive snapshots generated by the same scene shaders and display colour pass as the wallpaper. Changing a colour or palette updates the preview. These are representative snapshots, not a live mirror of the desktop's current simulation state. Particles use a lower preview count. A shared 384 × 216 context, bounded snapshot cache, delayed refresh and automatic context release avoid continuous preview rendering. Stock thumbnails remain a fallback if WebGL snapshots cannot be produced.

## Efficiency and recovery

- Video/animated-image decoders pause per assigned display group. A shared wallpaper continues if at least one of its displays is visible.
- Fully covered desktops stop scheduling frames. Manual pause preserves the displayed frame; covered-screen hibernation still releases resources.
- Cursor polling slows on battery and stops at high frequency while paused, locked or hibernating. Audio capture stops on battery-pause and lock.
- Secure/locked desktop detection pauses all displays, independently of the covered-window preference.
- Auto quality begins at Balanced and upgrades only after sustained headroom. Frame-limit scheduling preserves fractional timing remainder.
- Sleep gaps trigger desktop reattachment and layout refresh. Explorer-parent recovery retries initial attachment failures too.
- A renderer heartbeat allows at most three automatic reload attempts per ten minutes. This is a recovery aid, not a guarantee against every native GPU/WebView crash.
- Media loads have cancellation and a video-load timeout. Decoder stalls get two reload attempts; persistent errors fall back to Living Silk and report the problem in Studio. Restart wallpaper retries the source.
- Video position is retained in memory across covered-screen hibernation. A full renderer restart starts playback anew.
- GPU memory accounting is corrected, and unchanged pause states no longer restart animation decoding.
- Hover previews stop on blur/tab change and release their temporary media URLs.

## Desktop controls and settings

Tray: Open Studio, Pause/Resume, Next wallpaper (all displays), Restart wallpaper, Back up settings, Quit. System → Maintenance provides Restart, Backup and Restore. Ctrl+O opens the file picker in Studio.

Settings writes are serialized, synced and replaced, retaining the last valid configuration. Startup can recover a valid backup if the main JSON is corrupt. Write errors and startup-registration errors are surfaced instead of silently ignored. Display-slider writes are coalesced.

A manual backup is stored as `settings-backup.json` alongside the app configuration. Restoring preserves current Windows startup registration and saves the replaced settings as `settings-before-restore.json`. Backups contain settings and media paths, not copies of media assets.

## Validation

Passed locally: JavaScript syntax checks, JSON validation, and Node regression tests for decoder pause idempotence, texture memory accounting, stale asynchronous loads, bounded decoder recovery, per-monitor pause decisions, shared-display visibility, covered-frame scheduling and UI element wiring.

Rust persistence tests are included for replacing existing settings, corrupt-file recovery, backup preservation and write errors. The Windows CI workflow runs those tests and Clippy. They have **not** been run here: this environment has no Rust/Windows toolchain or installed browser runtime. WebGL rendering, responsive layout and native behaviour require the checks below on Windows.

## Windows acceptance checks

1. Start the app, open/close Studio repeatedly and reopen it from the tray. Run a second instance; it should focus the existing Studio.
2. Toggle the eagle by clicking the card and by keyboard. Check Customise and Pause do not toggle it. Rename a wallpaper and verify field selection works while panel/text selection does not.
3. Change each simulation's colours and palettes; compare the preview's appearance with the desktop. Verify colours and the eagle setting persist after restarting.
4. On two monitors, assign different videos, then cover one monitor. Only that decoder should pause. Repeat with one shared wallpaper on both monitors.
5. Lock/unlock, sleep/wake, disconnect/reconnect a monitor and restart Explorer. Confirm assignments return and the wallpaper remains behind desktop icons.
6. Unplug power under Normal, Eco and Pause policies. Check resume after reconnecting power and verify task-manager totals across all app/WebView processes.
7. Import a missing/unsupported video, then try Restart wallpaper. Verify bounded recovery and the fallback. Test a long session with video and simulation wallpapers.
8. Create a backup, change settings, restore and verify the backup. Check Windows startup registration and the build's installer separately.
