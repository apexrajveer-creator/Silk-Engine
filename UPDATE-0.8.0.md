# Silk Engine 0.8.0 — reliability update

## What changed

- Settings commands reject failed disk writes instead of reporting success. Slider edits are serialized, coalesced and retained for retry. Closing Studio, taking a backup, importing settings and resetting preferences wait for pending slider and widget saves.
- System → Maintenance adds Save pending changes, Export settings, Import settings, Reset preferences, Undo preference reset and Diagnostics. Reset preserves the wallpaper collection, assignments and widget layout; it resets wallpaper appearance, display and power preferences. Startup registration is preserved. Import validates the settings version, structure, limits and wallpaper IDs and keeps a recovery copy. Exports contain settings and file references, not wallpaper media.
- Settings backups are staged and synced before replacing an older backup. Invalid settings cannot overwrite a valid configuration. Malformed primary settings fall back to a valid backup or defaults. Generated wallpaper IDs have an atomic sequence and no longer rely on sleeping between imports.
- Invalid frame limits, quality values, colours and numeric settings fall back to supported defaults or bounds before reaching the renderer.
- Desktop visualizers honor battery-pause and manual-pause policies. Locked and hibernating desktops stop widget rendering. Rebuilding widget canvases cancels outstanding timers and releases old canvas buffers; a missing drawing context cannot crash the entire widget loop.
- Desktop cursor polling slows down immediately when every monitor is covered. Wake-up visibility state is published before renderer recovery events. Renderer boot failures and uncaught errors no longer keep reporting a healthy heartbeat indefinitely; existing bounded recovery can act on them.
- An asynchronous web-wallpaper load cannot attach a stale frame after its wallpaper has been replaced. Spanned web wallpapers remain visible while any assigned display is visible.
- Native file picking uses the registered dialog plugin command. Browser media storage rejects failed transactions and closes database connections. Disposed native event listeners cannot remain attached after registration finishes.
- Studio shows a recovery message and reload action if startup fails. Reduced-motion styling disables UI transitions and animations. Existing layout and nonselectable panels are retained.
- Discover uses Windows native TLS for native downloads, avoiding the extra default TLS implementation. Discover's backend still needs the setup described in backend/SETUP.md; this release does not deploy it.

## Updating from 0.7

1. Quit Silk from the tray and stop the development command.
2. Extract this ZIP to a fresh project folder. If you configured the community service, copy your previous src/community/config.json into the new folder.
3. Run `npm ci`, then `npm run dev`. Use the Cargo.lock included in this package; it was generated by Cargo and uses block2 0.6.2.

The application identifier remains com.echelon.silk, so the new source uses your existing app settings and downloaded wallpapers. Keep your old project folder until you have verified the new build. Build an installer with `npm run build`.

## Verification completed

- 40 JavaScript regression tests passed, including failed-save retry, ordering of edits arriving during a save, rendering-value validation, power policies, widget rendering and media recovery.
- Six Rust configuration tests executed successfully on Linux against the actual config.rs source: repeated replacement, corruption recovery, manual backups, invalid destination, invalid imports, safe rejection and unique IDs (some tests cover several cases).
- `cargo check --locked --target x86_64-pc-windows-gnu` passed for the application and with `--tests` for all Rust test code. This is a cross-target type/compile check, not a linked Windows executable or a Windows runtime test.
- Windows-target Clippy passed with warnings treated as errors. Rust formatting passed.
- Fresh Cargo lockfile generated; locked MSVC-target dependencies fetched successfully. npm audit reported zero vulnerabilities, including development dependencies, at the time of this check. This is not a complete security audit.
- Frontend verification parses every stylesheet, checks JavaScript syntax and relative imports, verifies HTML asset paths and unique IDs, and checks version agreement. It runs before dev and build. This catches the stylesheet corruption that broke 0.7.

## Remaining Windows release gates

The browser test suite was added but could not execute in this environment because browser startup is blocked by socket permissions. It checks Studio startup, CSS, navigation, HiDPI widget creation/persistence, diagnostics and blocked drag-selection. Both CI workflows run these tests before the native checks or release build. Run `verify-windows.cmd` to execute the local Windows checks.

Before calling this a stable public release, verify on actual Windows hardware:

- Launch and exit from the tray; change sliders and immediately close Studio; reopen and confirm settings survived.
- Save/export, change appearance, import and undo a reset. Confirm startup registration and the wallpaper files remain usable.
- Plug/unplug monitors; test differing resolutions and 100%, 150% and 200% display scaling.
- Lock/unlock, sleep/wake, restart Explorer, and return from fullscreen games. Check video playback and widget positions recover.
- Unplug power with Eco and Pause selected; confirm visualizers stop/react appropriately and wallpapers resume on AC.
- Remove or rename a wallpaper source file and confirm fallback/recovery messaging.
- Leave video, simulation and widget combinations running for an extended period; measure process memory, CPU and GPU use on more than one PC.

These hardware/runtime checks and measured performance claims are not completed by the automated source checks above. No signed installer or public release has been produced in this session.
